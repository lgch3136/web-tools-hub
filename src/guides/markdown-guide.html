一篇 Markdown 如何进入公众号、头条和网页

Markdown 最省时间的地方不是少打几个符号，而是把内容与发布样式分开：同一份源稿可以预览为公众号长文、头条资讯或技术文档，不必为每个平台重新改一遍正文。

这篇指南不从“# 是一级标题”开始背语法，而是完成一个可检查的任务：创建本地草稿，整理结构，加入图片、公式和图表，选择主题，复制到发布后台，再保留一份可继续编辑的源文件。

先打开工作台： Markdown 发布工作室。下文中的“草稿”“主题”“富文本复制”等名称均指这个页面里的真实操作。

先理解工作台的一个原则：Markdown 是唯一源稿

编辑器以 Markdown 文本为准，预览、富文本、HTML、DOCX 和打印结果都从它生成。这样做比同时编辑左右两块富文本更可靠，因为不会出现“预览改了，但源稿没有同步”的分叉。

  • 可恢复：草稿自动保存在当前浏览器的本地存储中。
  • 可迁移：随时下载 .md，不被某个网页或专有格式锁定。
  • 可复用：正文不变，只切换主题和排版参数。
  • 可核对：复制前先看预览；发布后再与预览逐项比对。
本地草稿不是云备份。换浏览器、清理网站数据或使用无痕窗口，都可能看不到原来的草稿。重要文章请同时下载 Markdown 文件。

完整发布流程

步骤一：建立可识别的本地草稿

  1. 在左侧草稿栏选择“新建”，给文档一个可辨识的名称，例如“8月产品复盘”。
  2. 第一行写一级标题；正文中只保留一个一级标题，章节从二级标题开始。
  3. 观察保存状态从“正在保存”变为“已保存”。它表示内容已写入当前浏览器，不表示已经上传到服务器。
  4. 长文开始前先下载一次 .md 作为外部备份。

同一篇稿件需要多个版本时，使用“复制草稿”比在正文里反复撤销更稳妥。例如保留“长文版”和“头条精简版”，两份都能继续修改。

步骤二：用结构表达含义，不用空格模拟排版

目的推荐写法不要这样做
文章标题# 标题连续输入很多空格居中
章节## 章节、### 小节只把文字加粗当标题
强调**关键结论**整段全部加粗
步骤有顺序用编号，无顺序用项目符号手工输入“1、2、3”后混用空格
待办- [ ] 待处理使用不统一的方框字符
数据Markdown 表格用制表符拼列
引用> 引用内容用双引号包住多段文字

工具栏会在光标或选中文本处插入规范语法。常用快捷键是 ⌘/Ctrl+B 加粗、⌘/Ctrl+I 斜体、⌘/Ctrl+K 插入链接、⌘/Ctrl+S 立即保存。

步骤三：插入目录、图片、代码、公式和图表

目录

在希望出现目录的位置输入 [TOC]。目录来自二级及以下标题；改标题后会随预览更新。标题相同时，工作台会生成不同的锚点，避免点击目录时跳错位置。

图片

可以粘贴或拖入本地图片。工作台会在浏览器里缩放、压缩并以数据地址插入 Markdown。这个方式适合草稿和离线 HTML，但有两个边界：

  • 数据地址会显著增大草稿体积，浏览器本地存储有容量上限。
  • 部分内容平台会过滤数据地址图片。正式发布前，应确认目标平台已经接管图片；否则先上传到自己的图床，再使用 HTTPS 图片地址。

外部图片地址会由浏览器直接请求图片服务器；该服务器可能看到你的 IP、User-Agent 和来源信息。敏感截图应先清理元数据并决定是否适合联网加载。

代码块

```javascript
const result = items.filter(item => item.ready);
console.log(result);
```

语言名决定语法高亮。高亮失败时仍会显示安全的纯文本代码，不会为了“高亮”执行代码。

数学公式

行内公式：$E = mc^2$

块级公式：
$$
\frac{a}{b} + \sqrt{x}
$$

公式使用 KaTeX 渲染。遇到不支持的命令时，应先缩小到最短公式，再对照 KaTeX 支持列表；不要把渲染失败的源代码当成已经发布成功。

Mermaid 图表

```mermaid
flowchart LR
  A[草稿] --> B[预览]
  B --> C[富文本复制]
  B --> D[HTML / PDF / DOCX]
```

图表在预览中按需渲染。复杂图表建议先参考 Mermaid 语法参考。复制到第三方编辑器时还要确认 SVG 是否被保留；如果平台删除 SVG，可先导出 HTML 或将图表转成图片后再发布。

步骤四：选择发布主题，再微调参数

主题适合内容核对重点
Clean网页文章、通用文档标题层级与表格宽度
WeChat公众号长文段落间距、引用和图片是否被后台保留
Toutiao头条资讯、观点文标题不要过长，移动端行宽是否舒适
Developer技术教程、API 说明代码横向滚动与深色背景
Notebook读书笔记、随笔衬线字体在目标设备上的替代效果

主题解决整体版式，字体、字号、行高、强调色和宽度解决局部适配。推荐顺序是：先选主题，再调行宽和字号，最后改强调色。一次改太多参数，会让你难以判断究竟哪一项改善了阅读体验。

点击“手机预览”只是在桌面上模拟窄画布，不等同于目标平台的真实渲染。发布前仍要在手机端打开草稿预览。

步骤五：复制到公众号或头条后台

  1. 先保存源稿并检查预览。
  2. 点击主操作“复制富文本”。工作台会把关键样式写入各个 HTML 元素，尽量减少目标编辑器丢失外部 CSS 的问题。
  3. 切换到目标平台编辑器，使用普通粘贴，不要先粘贴到纯文本软件。
  4. 逐项核对：标题、列表编号、引用、表格、链接、代码、图片、公式或图表。
  5. 发现某个平台大量删除样式时，尝试“复制 HTML”或导出 HTML，而不是反复修改 Markdown 源稿。

浏览器只有在 HTTPS 页面并获得剪贴板权限时，才能稳定写入富文本。若主操作失败，工作台会尝试兼容回退并给出状态提示。剪贴板能力与限制可参阅 MDN Clipboard API。

步骤六：保存可继续编辑、可交付和可打印的版本

  • Markdown：最重要的源文件，便于继续编辑和版本管理。
  • 独立 HTML：包含当前主题样式，适合归档、浏览器打开或放到静态站点。
  • 纯文本：适合只需要文字的投稿系统，但会失去层级和样式。
  • DOCX：方便交给习惯 Word 的协作者；复杂代码、图表和数学排版可能与网页预览不同。
  • 打印 / 保存 PDF：由浏览器打印引擎生成。打印前检查纸张尺寸、边距、分页和背景图形选项。

发布前的五分钟验收

  1. 源稿：下载的 .md 能重新导入，标题和正文完整。
  2. 结构：页面大纲与正文标题一致，没有从二级标题突然跳到五级标题。
  3. 链接：至少点击一个内部目录链接和一个外链；启用外链脚注时检查编号与原链接对应。
  4. 富媒体：逐个查看图片、代码、表格、公式和 Mermaid 图表的错误提示。
  5. 目标平台：粘贴后在桌面预览和手机预览各检查一次，不以工作台预览代替平台预览。

常见问题与定位方法

现象常见原因处理顺序
公众号粘贴后样式变少平台过滤标签或 CSS 属性使用“复制富文本”→重新粘贴→改用更简单主题→必要时复制 HTML
图片在预览中有，发布后没有平台拒绝数据地址或外链防盗链把图片直接上传到平台或可信图床，再替换地址
草稿突然消失换浏览器、无痕模式或清理了网站数据检查当前浏览器配置；从已下载的 Markdown 重新导入
保存提示容量不足大量数据地址图片占满本地存储立即下载 Markdown；移除大图；改用 HTTPS 图片地址；删除不用的草稿
DOCX 与预览不完全相同网页 CSS 与 Word 文档模型不同把 DOCX 当作可编辑交付版；要保留视觉版式时使用 HTML 或 PDF
公式或图表显示源码语法错误、浏览器加载增强模块失败保留原文→检查最小示例→刷新→按安全回退提示处理

数据边界：哪些留在本机，哪些会联网

  • Markdown 正文、导入文件解析、草稿和排版设置在浏览器本地处理。
  • 导入 DOCX 使用浏览器中的解析库，不需要上传文档到 Practical Tools 服务器。
  • 工作台页面不主动加载广告脚本；本指南属于内容页，可能加载 Google 广告服务。
  • 外部图片、外链、浏览器扩展以及你打开的第三方平台有各自的数据处理规则。
  • 清除草稿只影响当前浏览器本地副本；已经下载、复制或发布到其他平台的版本不会一并删除。

语法标准与兼容范围

基础语法以 CommonMark 为参考；表格、任务列表和删除线等扩展遵循常见的 GitHub Flavored Markdown 行为。不同平台并不保证接受同一套 HTML，因此“Markdown 渲染正确”和“第三方编辑器完整保留样式”是两个需要分别验收的环节。

FAQ

关闭页面后草稿还在吗？

通常还在，因为草稿保存在当前浏览器的本地存储。清除网站数据、无痕模式结束、浏览器策略或存储损坏都可能使它消失，因此重要稿件必须另外下载 Markdown。

能直接把公众号文章导回 Markdown 吗？

可以先把可访问的 HTML 保存为文件再导入，但平台生成的复杂样式、组件和图片地址会在转换时简化。转换结果应作为可编辑草稿，而不是原页面的像素级复制品。

富文本复制为什么需要 HTTPS？

浏览器将剪贴板视为敏感能力，通常只在安全上下文和用户主动点击后开放。Practical Tools 线上站点使用 HTTPS；本地开发时建议使用 localhost。

工作台会执行 Markdown 里的 HTML 或脚本吗？

不会。预览会清理不安全标签、事件属性和危险 URL。代码块只作为文本展示。这样可能牺牲少量自定义 HTML 能力，但可以避免把粘贴来的内容当成网页程序执行。

什么时候选 HTML，什么时候选 PDF？

需要继续发布、检索或适配不同屏幕时选 HTML；需要固定版面、发送审核稿或打印时选 PDF。仍需继续写作时，Markdown 才是首选源文件。
