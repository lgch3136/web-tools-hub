关于 Practical Tools

Practical Tools 是一个由独立开发者维护的浏览器工具站。目标不是把同一种小功能拆成大量页面，而是把常见任务做完整：输入、处理、检查、复制或导出，尽量在一个页面内完成。

我们正在解决什么问题

临时处理 JSON、图片、Markdown、编码或文本时，安装大型软件往往不划算，随意把文件上传到陌生服务也并不合适。本站因此优先采用浏览器端处理，并把结果保留、下载和错误反馈作为工具的一部分。

目前的重点产品是 Markdown 排版编辑器：它把实时预览、公众号与头条样式、富文本复制、导入导出、本地草稿和文章统计组合在同一工作台中。其他工具则围绕开发、文本、图片和日常转换场景维护。

三条产品原则

1. 先完成任务，再谈页面数量

一个可反复使用的深度工具，比十个只做一次转换的薄页面更有价值。新功能会优先补齐真实工作流，而不是只增加关键词相近的入口。

2. 本地优先，但不夸大边界

文本转换、密码生成、Hash、图片压缩等主要计算在浏览器中完成。Markdown 草稿会写入当前浏览器的本地存储，直到你主动删除或清理站点数据。汇率工具需要请求公开汇率数据；带广告的内容页面也会连接 Google。完整边界见 隐私政策。

3. 写清限制和失败状态

浏览器能力、文件格式和第三方编辑器都有兼容差异。我们会在界面和指南中说明限制，不把“无需上传”写成“绝对安全”，也不承诺所有浏览器和所有文档都能得到完全一致的结果。

数据处理边界

  • 浏览器本地处理：大多数文本、编码、密码、Hash 和图片任务。
  • 浏览器本地保存：Markdown 编辑器的草稿、排版偏好和部分站点设置。
  • 需要网络：页面本身的静态资源、汇率数据、少数前端库，以及首页和指南页的广告服务。
  • 没有本站账户系统：当前不要求注册，也没有由本站运营的用户内容数据库。

技术与可验证信息

本站采用 HTML、CSS、JavaScript 和 Parcel 构建，部署在 Vercel。源码公开在 GitHub 仓库，可以直接查看实现、提交记录和已知问题。具体工具可能使用 Web Crypto、Canvas、Clipboard、File API，以及随前端打包或从公共 CDN 加载的开源库。

反馈与纠错

如果某个工具输出不正确、说明与实际行为不一致，或移动端无法完成任务，请在 GitHub 提交 Issue，或发送邮件到 lgch3136@gmail.com。报告中附上浏览器版本、输入示例和复现步骤，会更容易定位问题。
