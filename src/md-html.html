Practical workflow

从草稿到发布，一条可复查的流程

这个工作室把“写 Markdown”和“给发布平台排版”放在同一页，但始终以 Markdown 源文档为准。这样修改、备份和迁移都更容易。

  1. 01

    先保存可迁移的源稿

    新建一个命名文档后直接写作。自动保存只负责当前浏览器的恢复；重要文章应定期导出 .md 文件。

  2. 02

    用结构而不是空格排版

    使用标题、列表、引用、表格和 [TOC]。这些结构能稳定转换为 HTML、Word 和富文本，手工空格在不同平台通常会丢失。

  3. 03

    按目标平台检查预览

    WeChat 和 Toutiao 主题强调中文阅读节奏；Developer 适合代码；Notebook 适合长文。字号、行高、强调色和正文宽度会一并用于富文本复制与 HTML 导出。

  4. 04

    发布前做一次目标编辑器粘贴测试

    优先使用“复制富文本”，粘贴到公众号或其他编辑器后检查图片、表格和代码块。平台可能二次清理 CSS，所以最终结果应以目标编辑器为准。

What is exact

功能边界写清楚，导出时才不会意外

Markdown 渲染
支持 marked 提供的 GFM 表格、任务列表、删除线和围栏代码。原始 HTML 会作为文本处理，不会在预览中执行。
代码、图表与数学
常见语言使用本地语法高亮；Mermaid 图表与 KaTeX 公式仅在文档需要时加载。增强模块无法载入或源码无法解析时，预览会保留可读源码并显示明确提示。
导入
.md、.markdown、.txt 直接读取；HTML 清理后转为 Markdown；DOCX 通过 Mammoth 提取结构，复杂页眉、浮动对象和精确版式不会保留。
导出
Markdown 和 TXT 适合长期备份；独立 HTML 包含当前主题；DOCX 保留常见标题、段落、列表、链接、代码和表格；PDF 使用浏览器的打印 / 另存为 PDF。
图片
粘贴或拖入的 JPEG、PNG、WebP 会在尺寸较大时压缩并以内嵌数据保存；GIF 保持原文件。大量内嵌图片可能超过浏览器存储额度。

Privacy & limitations

本地处理不等于永久备份

草稿、偏好和粘贴的本地图片保存在浏览器的 localStorage 中，本工具没有账号同步。无痕窗口、浏览器清理、设备更换或站点数据重置都可能让草稿消失。

文档中的远程图片链接仍会由浏览器向图片所在网站发起请求。若内容敏感，请删除远程资源或改用本地图片。DOCX 导入和所有导出在页面内完成；本页不包含广告脚本。

FAQ

发布前常见问题

为什么粘贴到公众号后略有变化？

发布平台会过滤它不接受的样式。富文本复制已把关键计算样式写入元素，但平台仍可能调整字体、外边距或代码块背景。

怎样得到 PDF？

选择“导出 → 打印 / 保存 PDF”，在系统打印面板中选择“另存为 PDF”。这种方式比画布截图更能保留文字清晰度和分页能力。

HTML 导入安全吗？

导入内容先经过标签、属性和 URL 协议白名单，再转换成 Markdown。脚本、事件属性、嵌入页面和表单控件不会进入预览。

可以在另一台设备继续吗？

不会自动同步。请下载 Markdown 文件，在另一台设备上重新导入；这也是最稳妥的长期备份方式。

DOCX 为什么与原稿不完全一样？

Markdown 没有 Word 的分页、文本框和浮动排版概念。工具保留可映射的内容结构，不承诺复刻原 Word 页面。

能直接写 HTML 吗？

可以把 HTML 文件导入并转成 Markdown，但编辑器不会执行 Markdown 中的原始 HTML。这样能避免脚本或危险属性进入发布预览。
